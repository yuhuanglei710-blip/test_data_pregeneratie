# Automation Console

通过前台接口、后台接口和测试工具预生成测试数据，用于简化复杂功能的测试准备工作。

第一次参与开发，请先阅读 [零基础开发说明书](doc/DEVELOPMENT_GUIDE.md)。它包含启动步骤、
代码地图、一次操作的完整调用链、新增页面/API/后台任务的方法、测试命令和常见故障处理。

## 目录结构

- `api/`：后台等通用 API 客户端。
- `base/`：用户注册、加钱、下注及批量账号工作流。
- `gui.py`：主窗口页面组装和业务交互。
- `gui_theme.py`、`gui_widgets.py`、`gui_workers.py`、`gui_dialogs.py`：界面主题、通用控件、后台任务和弹窗。
- `tool_pages.py`：时间戳、SSH 主机和快捷访问页面。
- `tools/`：时间戳等无业务依赖的工具。
- `test/`：不访问网络的单元测试。
- `cache/`：token 等临时缓存。
- `env.json`：运行环境、平台、下注和本地工具的统一配置。

## 安装

建议使用虚拟环境，并安装项目依赖：

```shell
pip install -r requirements.txt
```

启动前检查根目录 `env.json`。前台和后台地址按环境集中配置：

```json
{
  "environment": {
    "dev": {
      "domain": "前台接口域名",
      "back_ground_url": "后台接口域名"
    }
  }
}
```

下注接口、Origin、游戏参数、默认单注和请求重试配置统一位于 `spin`；本地数据路径及旧系统
迁移参数位于 `local`。程序不再读取 `.env`、`dev.env` 等传统环境文件。

## 使用

启动图形界面：

```shell
python main.py
```

界面在“数据准备”分组下提供账号生成、锦标赛造数、玩家分层和用户查询四个功能页。“账号生成”可选择按原逻辑批量注册随机邮箱账号，或使用
自定义邮箱定制创建一个指定账号；两种方式都会导出账号信息。创建账号时不再手动填写
Channel Code，而是选择是否进入 B 面及是否启用新手套路：不进入 B 面固定使用 `Organic`，
进入 B 面时根据日志库 `log_user_source` 的 `enter_pkg` 与 `cfg_channel_group` 自动匹配渠道源。
“更新参数”会从 `ush_log_<环境>` 刷新渠道参数并缓存到本机
`cache/channel_sources.json`。“锦标赛造数”会注册
账号、加钱并完成固定或随机次数的下注。账号处理和下注都能分别选择串行或并行；串行
模式会固定使用一个执行线程，并禁用对应的并发数。界面会实时显示运行日志及完成进度，
注册平台可选择 Android 或 iOS。左侧导航按“数据准备、接口与流程、设备工具、系统”分组，
可在账号生成、锦标赛造数、玩家分层、用户查询、SQL 数据模板、API 请求模板、自动化场景、Android 安装、
iOS 安装、Android 日志、时间戳工具、SSH 主机、快捷访问和环境与参数之间切换；环境与参数页维护的 Channel Code 作为两个账号任务页的渠道匹配优先级，页面也可
维护 SSH 数据库连接。两类配置都按运行环境
隔离，切换环境时会自动加载对应参数。数据库连接通过 SSH 隧道访问 MySQL，SSH 只允许
使用界面导入的私钥文件，不使用密码、SSH Agent 或自动密钥搜索，并可在界面中测试连接。
环境与参数页的环境选择框旁会以红色或绿色呼吸状态显示数据库是否已配置，点击状态入口
可配置或编辑当前环境的连接参数。SSH 私钥在环境与参数页的私钥库中单独导入和维护，各环境连接
只需选择已导入的私钥；仍被环境引用的私钥不能删除。
每个环境可分别设置业务库和日志库名称，更新渠道参数时会读取当前环境配置的日志库。
连接信息保存在本机 `cache/database_connections.json`（已排除版本控制），数据库密码不会
输出到运行日志。
批量任务只维持当前并发数的待执行账号，不会一次性创建全部任务。点击“停止”后会立即
停止派发新账号并取消尚未开始的任务；当前正在进行的网络请求使用 10 秒超时，退出后
界面恢复操作。进度仅统计实际执行完成的账号，不把取消任务显示成完成。绑定 SQL 或
包含 SQL 的自动化场景会复用同一环境的 SSH 隧道，并限制并发数据库连接，避免批量任务
为每个账号同时建立 SSH 握手。

## 玩家分层

“玩家分层”页支持按环境和 UID 读取 `user.charge_total`（累计充值）、
`user.withdraw_total`（累计提现）、`user.money` 与 `user.bonus`，当前余额按
`user.money + user.bonus` 计算，金额均使用数据库原值“分”。
构造时会同时设置目标 `vip_level`；通用玩家可选择 VIP4、VIP5 或 VIP6，对应严格累计充值
门槛分别为 `350000`、`1600000`、`8000000` 分，并使用 `400000`、`1650000`、
`8050000` 分作为安全构造值。
构造时可直接选择“通用玩家”或“FB 玩家”，不会读取或识别账号当前渠道；FB 与 FBWeb
统一使用 FB 构造规则。通用玩家的累计充值门槛为 `350000` 分，未超过门槛时使用
`400000` 分安全构造值；FB 玩家的门槛为 `20000` 分，未超过门槛时使用 `25000` 分
安全构造值，避免数据正好卡在服务端边界。
构造目标分层时还可选择注册时长：选择“大于7天”时，不满足条件的账号会把
`user.created_at` 调整为 8 天前；选择“7天内”时，原本在 7 天内的账号保留原时间，
已超过 7 天的账号调整为 5 天前。已满足所选条件的注册时间不会被改写。
如果选择“大于7天”且账号当前仍在 7 天内，页面会按 UID 从数据库读取邮箱和平台，并使用
默认密码 `123456` 的一次 MD5 自动登录获取用户 Token（数据库中的密码为二次 MD5，不用于
登录）；随后先加钱，再重新登录刷新因账户变更而失效的用户 Token，完成下注并形成必要
流水后才修改注册时间和分层数据。该能力与锦标赛造数共用同一套加钱、登录刷新、下注和
失败校验逻辑。

净利润与利润率按以下公式计算：

```text
当前余额 = user.money + user.bonus
净利润 = 累计充值 - 累计提现 - 0.07 × 累计充值 - 0.035 × 累计提现 - 当前余额
利润率 = 净利润 ÷ 累计充值
```

累计充值为 0 时显示“未分层”；否则先判断净利润：净利润严格大于 `1000000` 分
（`$10,000`）时直接判定为顶级玩家；等于该边界时不触发，继续按利润率判断。利润率分层为
套利用户（小于 -1%）、普通用户（大于等于 -1% 且小于 10%）、核心玩家（大于等于 10%
且小于 20%）和顶级玩家（大于等于 20%）。服务端要求累计充值至少达到 `350000` 美分才参与分层。“一键构造
目标分层”会保留高于门槛的原累计充值；未达门槛或正好处于门槛时使用 `400000` 美分的
安全构造值，避免卡在服务端边界。随后将累计提现设为 `0`，并按实际充值额调整余额以命中
目标利润率。目标列表另提供“净利润顶级玩家”，使用至少 `7000000` 分累计充值和 15% 利润率，
构造净利润 `1050000` 分；该利润率原本属于核心玩家，因此可明确验证净利润规则先于利润率。
套利目标会确保净利润不高于 `-50000` 分，不再使用容易落入观察期的固定 -2% 数据；
`-50000` 是观察区间的排除边界，可以立即参与利润率分层。
该操作会
更新 `charge_total`、`withdraw_total`、`money`、`bonus` 和 `vip_level`，并在写库前要求确认。构造时优先保留
现有 `bonus` 并用 `money` 补足目标总余额；当现有 `bonus` 已超过目标总余额时，会将 `bonus`
压到目标值并把 `money` 设为 `0`。右侧“手动输入预览”
仅在本地计算，不连接或修改数据库。按 UID 读取以及构造完成后，还会读取
`user_base.user_segment` 并原样显示服务端保存的分层结果；本地利润率分层会单独标记为
“公式分层”。写库完成时展示的 `user_segment` 是服务端当时的当前值，服务端异步刷新前可能
仍是旧分层，界面不会把它误报为本次构造后的结果。

## 用户查询

“用户查询”页支持按 UID 精确查询，也支持按邮箱关键字模糊查询；邮箱命中多条记录时可从
匹配列表中选择用户。页面在同一信息区展示基础信息，并原位提供 `pkg_name`（`a`、`b`、
`web`）、`platform`（`1`、`2`、`3`）、`user_base.user_segment`、`vip_level`、
`charge_total`、`money`、`bonus`、`withdraw_total`、`charge_times` 和 `withdraw_times` 的编辑。
`money` 与 `bonus` 独立展示，不额外计算总余额。查询和保存都复用所选环境的数据库连接，
并使用参数化 SQL 操作；保存前会列出实际变更并要求确认，未配置数据库连接时不会执行查询
或写入。查询到用户后，还可直接选择缓存中声明了 `@uid` 或 `@userid` 的 SQL 模板：当前 UID
自动绑定，其他参数原位填写，确认后在当前环境执行并自动刷新用户数据。SQL 模板缓存中同时
提供“修改用户分层”，可按 `userid` 和 `usersegment` 独立执行。

## Android 设备安装

“Android 安装”页会在进入页面时检测 Android 设备，之后只在点击“刷新”时再次检测，不会定时
刷新整个页面；同时支持选择 APK，或把单个本地 `.apk` 文件拖入添加区，再沿用相同的归因链接和
“缓存并添加”流程建立本地缓存。安装包按
MD5 去重，缓存文件和元数据分别保存在 `cache/apks/` 与
`cache/apk_packages.json`。每个缓存项可维护显示名称、归因链接和备注，并可单独执行安装、
打开归因链接或“归因+安装”。归因链接使用不限制文本长度的多行输入，并通过 ADB 标准输入
发送，避免受到 Windows 命令行长度限制。ADB 默认从系统 `PATH` 查找，也可通过 `ADB_PATH` 环境变量
指定完整路径。

安装默认使用 `adb install -r -d`，允许覆盖和降级。如果设备上存在同包名但签名不一致的
旧应用，界面会显示旧包名，并在卸载前询问是否替换；只有确认后才会卸载旧应用并安装新包，
同时明确提示卸载会清空该应用的本地数据。

## iOS 设备安装

“iOS 安装”页支持选择本地 IPA，或从 `http://` / `https://` 地址下载 IPA。下载内容先写入
临时文件，读取包信息后按 MD5 写入 `cache/ipas/`，元数据保存在
`cache/ipa_packages.json`。缓存和安装流程仅读取 IPA 的 Bundle ID 及可选的描述文件信息，
不进行本地签名、证书期限或设备白名单校验，是否允许安装由 iOS 在安装阶段判断。

iOS 真机连接和 IPA 安装使用 `tidevice`；Safari 打开链接使用 `pymobiledevice3` 的
Web Inspector 接口，避免新版 iOS 上旧 `tidevice launch` 下载开发者镜像失败。
Windows 上需安装可用的
Apple Mobile Device 驱动/服务，并在已解锁的 iPhone 上信任当前电脑。每个缓存项都可以
单独安装、打开归因链接，或执行“归因+安装”；组合操作的顺序为读取包信息、Safari
打开归因链接、安装 IPA。安装失败时显示 tidevice 返回的错误。

首次配置 Safari 控制环境（Windows，Python 3.10 及以上）：

```powershell
python -m venv cache/ios-runtime
cache/ios-runtime/Scripts/python.exe -m pip install -r requirements-ios.txt
```

程序优先使用这个独立环境，不改动主程序的 Python 依赖；其他系统的虚拟环境解释器为
`cache/ios-runtime/bin/python`。也可以在主程序环境安装 `requirements-ios.txt`。
在 iPhone「设置 → App → Safari → 高级」中开启「Web 检查器」，
并保持设备解锁、信任此电脑。旧 iOS 的 Safari 设置直接位于「设置 → Safari」。
如支持「远程自动化」，可以开启后使用自动化会话；未开启或没有此开关时，程序自动
使用普通 Safari 网页标签页（优先空白页，否则最新的可控制页面），在该页导航到归因链接。
首次使用时请在 Safari 打开一个普通网页；如没有可控制页面，程序会明确提示。
链接通过标准输入传递，不放入命令行；只有 Safari 确认导航完成后才继续安装。
Web 检查器未开启、导航失败或超时时会停止组合流程并提示原因，不会跳过归因直接安装。

## Android 应用日志

“Android 日志”页通过 ADB 实时读取 Android `logcat`。进入页面时会检测设备；选择设备后可读取
第三方应用包名，也可手动输入包名。留空应用会读取整机日志，选择应用时会先获取当前主进程
PID，再使用 `logcat --pid` 过滤，因此应用必须已经启动；应用重启导致 PID 变化后需要重新开始
抓取。最低日志级别支持 Verbose、Debug、Info、Warning、Error 和 Fatal，关键字过滤不区分
大小写。

“清空显示”只清空界面，不会删除手机日志。只有主动勾选“开始前清空手机 Logcat 缓冲区”时
才会执行一次 `adb logcat -c`，开始后该选项会自动复位。默认不清空时，会先读取符合条件的
现有 Logcat 缓冲，再继续实时输出。界面最多保留最近 20,000 行；如需长时间抓取，可在开始前选择
`.log` 输出文件，符合设备、应用和级别条件的完整输出会实时写入该文件，界面关键字过滤不会
删减文件内容；重复使用已有文件时会先确认是否覆盖。也可以随时将界面当前显示的日志另行导出。

注册单个开发环境用户：

```shell
python -m base.user
```

批量注册、加钱并下注：

```shell
python -m base.tournment_test
```

批量脚本会真实调用开发环境接口，并将成功创建的账号写入项目根目录下的
`accounts.txt`。运行前请确认 `env.json` 和界面中的数量、金额、下注次数符合预期。

注册默认使用精简日志；每次下注会输出一行紧凑的 JSON 结果。需要查看接口状态与完整
响应时，可在代码调用中传入 `verbose=True`。失败响应会保留状态码和截断后的响应内容。
批量流程会复用未过期的游戏 token。串行下注会将每次响应中的 `session_id` 传给下一次
下注；并行下注会复用 token，但每次请求使用独立 session。账号并发和单账号下注并发
可以分别设置。账号默认并发为 5；单账号下注默认使用串行模式（并发数 1），避免同一
token 的并发请求触发服务端限流或 session 冲突。单次下注失败后会按
`spin.spin_retry_delays` 的间隔重试，默认等待 0.5 秒、1 秒后各重试一次。
选择 `huidu` 灰度环境时，游戏 token 会从灰度 `self_game_url` 获取，网页 Origin、token
缓存和游戏 session 也会按环境隔离，不会与测试环境混用。
选择 `yy` 环境时，游戏 token 接口读取 `environment.yy.domain`，请求 Origin 和退出/收银
地址读取 `spin.environments.yy.web_origin`，不会回退到个人服接口。
所有环境的游戏 token 接口都会读取 `env.json` 中所选环境的 `domain`：`dev`、`huidu`、
`yy` 和 `individual` 分别使用自己的前台 API。未配置的环境会直接报错，禁止
静默回退到 dev 或个人服，避免把登录 Token 发送到错误服务。
默认单次下注金额读取 `spin.default_bet_cents`，也可通过 `bet_amount` 参数调整。

## 通用工具

“时间戳工具”支持解析 Unix 秒/毫秒时间戳、ISO 8601 和本地日期时间，展示本地、UTC、
UTC+8、UTC-8、相对时间及秒/毫秒值，并支持按小时计算偏移。

“SSH 主机”支持本地维护主机、密码或私钥认证、连接测试、执行远程命令，以及读取和修改
Linux 主机时间。主机时间页完整集成时间戳解析和偏移工具，支持 3 秒自动刷新、秒/毫秒复制；
首次读取会将主机时间填入编辑器，后续自动刷新不会覆盖正在编辑的目标时间。私钥复用“环境与参数”页的 SSH 私钥库，也可以在新增/编辑主机时导入；
主机信息保存在 `cache/ssh_hosts.json`。SSH 不使用 Agent 或自动密钥搜索。修改远程系统时间
通常需要 root 或等效权限。

“快捷访问”支持链接分类、置顶、检索、浏览器打开和摘要复制；选中链接后可在详情区单独复制
地址或登录字段，密码等敏感字段默认隐藏。每条链接可维护账号、密码、AppKey 等任意键值字段，
数据保存在 `cache/quick_access.json`。这两个本地 JSON 文件均已由
`cache/` 规则排除版本控制，但字段和密码仍属于本机明文数据，请妥善保护项目目录。

通用工具的数据文件位置统一在项目根目录 `env.json` 的 `local` 对象中配置，包括 `TOOL_DATA_DIR`、
`QUICK_ACCESS_FILE`、`SSH_HOSTS_FILE`、`SSH_PRIVATE_KEYS_FILE` 和 `SSH_PRIVATE_KEY_DIR`。
从旧 Java 测试平台重新迁移数据时，配置 `LEGACY_TEST_TOOL_*` 后执行：

```powershell
python -m base.legacy_tool_migration
```

迁移会合并本地新增数据，以 `legacy-*` 标识并更新旧平台记录；重复执行不会产生重复项。
旧平台数据库中的私钥会保存到 `SSH_PRIVATE_KEY_DIR`，对应目录和迁移备份均被 Git 忽略。

## SQL 数据模板

“SQL 数据模板”页可新增、编辑和删除命名 SQL 模板。模板使用 `@参数名=xxx;` 声明运行参数，
执行时会自动转换为 MySQL `SET` 语句，后续 SQL 可直接用 `@参数名` 引用。编辑弹窗支持输入
参数名并插入声明，例如：

```sql
@userid=xxx;
@viplevel=xxx;
UPDATE user SET vip_level=@viplevel WHERE id=@userid;
```

独立执行时，右侧会按声明顺序自动生成 `userid`、`viplevel` 等输入框，并用填写值替换 `xxx`；
数字、`true`、`false` 和 `null` 会保留对应类型，普通文本会安全转义为 SQL 字符串。在“账号生成”或
“锦标赛造数”页绑定 SQL 模板时，右侧日志上方会按模板动态显示参数栏；`@uid` 和 `@userid`
自动使用每个新创建账号的 UID，其余参数由用户统一填写并应用到该批账号。多条 DML 语句在同一数据库
事务中执行（DDL 遵循 MySQL 自动提交规则），模板保存在本机
`cache/sql_templates.json`（已排除版本控制）。
SQL 模板选择框支持按标题模糊检索；执行日志只输出模板名、UID 和成功状态。
“SQL 数据模板”页以标题列表管理模板，右侧为独立执行参数，底部仅保留紧凑日志栏。

## API 请求模板

“API 请求模板”页可按标题保存、检索、编辑和删除 HTTP 请求模板。模板支持
`GET`、`POST`、`PUT`、`PATCH` 和 `DELETE`，可配置接口路径、JSON 格式的 Headers、
Body 与请求超时时间。模板保存在本机 `cache/api_templates.json`（已排除版本控制）。
发送页选择 `dev`、`huidu`、`yy` 或 `individual` 后，会读取 `env.json` 中对应环境的
`domain` 并自动拼接以 `/` 开头的接口路径。
模板也可保存以 `http://` 或 `https://` 开头的完整 URL，此时域名固定，不随环境切换。

URL、Headers 和 Body 均支持 `{{参数名}}` 占位符，例如：

```text
/v1/user/{{userid}}
```

发送前在右侧运行参数中填写 JSON 对象：

```json
{"userid": 123, "token": "example-token"}
```

选择模板后，界面会自动生成参数骨架，也可用“生成参数”补齐缺少的字段；JSON 支持
一键格式化和 JSON 语法高亮。发送预览会实时展示并高亮渲染后的 URL、Headers 和 Body，
在参数缺失或格式错误时直接提示。请求就绪后可点击“发送请求”或按 `Ctrl+Enter`，底部
响应日志显示状态码、耗时和高亮后的响应正文，并支持一键复制。超长响应会自动截断，
避免日志区域持续膨胀。

API 响应按 `{code, data, msg}` 协议处理。字符串类型的 `data` 和 `msg` 会自动进行
Base64 解码；`data` 解码后若为 JSON，会继续解析成对象。独立请求日志显示解码后的响应，
自动化场景可直接断言 `response.code`、`response.data.xxx` 和 `response.msg`。

## 自动化场景

“自动化场景”页将已有 SQL 和 API 模板编排为有序步骤，支持以下步骤类型：

- SQL：修改或查询数据，最后一个查询结果可通过 `sql`（首行）和 `sql_rows`（全部行）读取。
- API：发送请求，响应写入 `response`，并提供 `http_status`、`elapsed_ms` 等字段。
- 提取变量：例如将 `response.data.order_id` 保存为 `order_id`，供后续 `{{order_id}}` 使用。
- 断言：支持等于、不等于、存在、不存在、包含、大于和小于。

步骤可标记为清理步骤，主流程失败或停止后仍会尝试执行。场景独立运行时可填写初始变量；
绑定到“账号生成”或“锦标赛造数”后，会自动提供 `userid`、`token`、`email`、`platform`
和 `channel_code`。场景保存在本机 `cache/feature_scenarios.json`，引用中的模板使用固定 ID，
被场景引用的 SQL/API 模板不能直接删除。
